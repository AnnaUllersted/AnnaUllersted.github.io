A development project exploring whether a parametric FE model could be turned into something faster: instead of running a full finite element analysis for every design variant, train a machine learning model to predict the result directly.

## The problem

The [Culvert Tool](/2026/08/28/culvert-tool.html) parametric FE model is accurate but not instant — every design variant still means a real FE run through SOFiSTiK. For quick sizing, early-stage iteration, or a self-serve tool for non-experts, waiting on a full analysis each time is a bottleneck.

## What I built

An AI/ML pipeline that learns to approximate the FE model's output directly from its inputs:

**Synthetic data generation.** The existing parametric FE model became a data factory: 5,000 synthetic box-culvert variants were generated by randomizing the input features across their valid ranges, each one run through the full FE pipeline to get real design values.

![Rhino and Grasshopper generating synthetic bridge variants](/assets/productized-bridges/synthetic-data-generation.png)
*Batch-generating synthetic bridge geometries as training data.*

**Feature correlation and processing.** Before training, the input and output features were checked for correlation to understand which parameters actually drive the design values, and the data was cleaned, transformed, and augmented.

![Feature correlation heatmap across geometry and design-value features](/assets/productized-bridges/feature-correlation.png)
*Correlation between geometry inputs and the resulting design forces/moments.*

**Model development, in phases:** first testing multiple ML model types against the data, then identifying their limitations, deriving additional features, and tuning the most suitable model with more advanced techniques until it worked as a reliable surrogate for the FE analysis.

**Shipping it as a tool.** The trained model isn't just a notebook result — it's live behind a [ShapeDiver](https://www.shapediver.com/) web app: a Grasshopper script generates the geometry, Python scripts call the model (hosted on an Azure server) and iterate over reinforcement configurations to validate a layout, all wired together through ShapeDiver's front end.

## The result

A design tool where changing a slider returns a predicted design — reinforcement layout included — in the time it takes a web app to respond, instead of a full FE analysis cycle.

![ShapeDiver app: sliders for tunnel geometry and the resulting required reinforcement](/assets/productized-bridges/shapediver-app.png)
*Adjust the geometry, get the required reinforcement back immediately.*

## Tools

Rhino · Grasshopper · Python · ShapeDiver · Azure (model hosting) · machine learning (scikit-learn / similar)
